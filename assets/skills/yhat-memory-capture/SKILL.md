# YHat Memory Capture Skill v0.1.1

## Purpose

Convert durable YHat knowledge emerged during conversation into structured v0.1.1 observations. When the `yhat-memory-capture` agent is selected for a session, this skill **selectively captures** — it records only knowledge that meets the durability and provenance criteria defined in this document.

## v0.1.1 Capture Contract

Every memory captured through this skill MUST include:

### Required Fields

| Field | Value | Notes |
|-------|-------|-------|
| `project` | Fixed to `yhat` | Always `yhat` |
| `type` | One of 11 PRD types | Determined by vocabulary mapping |
| `scope` | Fixed to `project` | Always `project` |
| `topic_key` | 2–3 segment dot-notation | `^[a-z][a-z0-9-]*(\.[a-z][a-z0-9-]*){1,2}$` |
| `title` | Short, descriptive title | Extracted from content |
| `content` | The actual knowledge statement | Conversation |
| `source` | `business-user`, `ai-agent`, or `validation-agent` | Who originated the claim |
| `status` | Fixed to `unverified` | Always `unverified` |
| `created_at` | ISO timestamp | Auto-generated by backend |
| `last_seen_at` | ISO timestamp | Auto-generated by backend |
| `source_session` | Session identifier | Runtime context |
| `source_workspace` | Workspace path or identifier | Runtime context |

### Optional Fields

| Field | Type | Default | Notes |
|-------|------|---------|-------|
| `confidence` | float (0–1) | 0.7 | Estimated confidence |
| `source_tool` | string | null | Tool that captured |
| `created_by` | string | null | Anonymized creator identifier |
| `related_topic` | string | null | For pending_observations |
| `review_after` | ISO timestamp | null | Scheduling hint |

### Field Semantics

- **`source`**: Who originated the claim (business-user, ai-agent, validation-agent). Do not conflate with `source_session`, `source_workspace`, `source_tool`, `created_by` which are provenance detail.

## Topic Key Normalization

Topic keys MUST follow the pattern: `^[a-z][a-z0-9-]*(\.[a-z][a-z0-9-]*){1,2}$`

This is 2–3 segments, lowercase letters/numbers/hyphens, no leading/trailing dots.

### Normalization Algorithm

```
1. Extract domain from content (fa, codes, aum, branch, auth, etc.)
2. Extract concept/action from content
3. If needed, add middle segment for specificity
4. Replace spaces with hyphens
5. Remove special characters except hyphens
6. Lowercase everything
7. Validate against pattern
```

### Examples

| Content Topic | Normalized topic_key |
|--------------|---------------------|
| "How FA display works" | `fa.display-format` |
| "Code to FA relationship" | `codes.fa-relationship` |
| "Branch mapping rules" | `branch.mapping-rules` |
| "Duplicate detection logic" | `aum.duplicate-detection` |
| "Code creation process" | `codes.creation-process` |
| "Three-segment key" | `domain.subdomain.concept` |

## Capture Eligibility Rules

### MUST Capture (Eligible)

✅ Durable operational knowledge (business rules, decisions, patterns)
✅ Verified facts from operational systems
✅ Technical standards and conventions
✅ Entity relationships and mappings
✅ Process descriptions
✅ Exception handling rules
✅ Data quality observations

### MUST Reject (Ineligible)

❌ **Secrets/Credentials**: Passwords, API keys, tokens, secrets, bearer, ENV vars containing secrets
❌ **Transient Summaries**: Session summaries, conversation transcripts, debug logs, session-log
❌ **Unconfirmed Drafts**: WIP, TODO, TBD, "I think", "might be" (frame as `assumption` instead if explicitly requested)
❌ **Personal Operational Data**: User-specific paths, local configs, session state
❌ **Pure Opinions**: Unverified assumptions without operational evidence (frame as `assumption`)
❌ **Chatty Content**: Greetings, acknowledgements, off-topic discussion

### Vocabulary Framing

If content is close to an ineligible pattern, try to frame it appropriately:
- "I think the separator should be a hyphen" → capture as `assumption` with topic key
- "TODO: verify this later" → ask to reframe as `assumption` or reject

## Rejection Patterns

### Secret Patterns (Reject Always)

```
- password, passwd, pwd
- secret, secreto
- token, api_key, apikey, api-key
- private_key, private-key, priv_key
- credentials, bearer
- aws_secret, aws_secret_access_key
- ENV vars with secret patterns
```

### Transient Patterns (Reject Always)

```
- summary, resumen, resumen de sesión
- transcript, transcripción
- conversation-log, session-log
- debug-output, error-trace, debug
- "last message was", "continuing from"
- session state, session summary
```

### Draft Patterns (Reject Always)

```
- draft, borrador, wip
- todo, tbd, tbc, to-do, TODO
- "[ ]", "check this later"
- "not sure yet", "might change", "might be"
```

### Personal Data Patterns (Reject Always)

```
- Local file paths with username (e.g., /home/username/...)
- Session-specific state variables
- Machine-specific configuration
- Temporary/debug variables
```

## Agent Behavior Protocol

1. **At session wrap-up or explicit trigger**: Ask one elicitation question
2. **Map vocabulary**: Use the vocabulary → type mapping table
3. **Normalize topic_key**: Apply the regex pattern
4. **Run eligibility**: Check against rejection patterns
5. **Assemble payload**: Fill all required fields + optional fields
6. **POST to /capture**: Send to backend
7. **Never publish automatically**: All observations start as `unverified`

### Elicitation Question Example

At session wrap-up:
> "¿Hay algo importante que capture durante esta sesión que deba registrarse en la base de conocimiento?"

On explicit trigger:
> "¿Debería capturar esto como conocimiento durable?"

## Validation Checklist

Before saving any memory, verify:

- [ ] `project` is `yhat`
- [ ] `scope` is `project`
- [ ] `type` is one of the 11 PRD taxonomy values
- [ ] `topic_key` matches `^[a-z][a-z0-9-]*(\.[a-z][a-z0-9-]*){1,2}$`
- [ ] `content` is a durable knowledge statement (not transient)
- [ ] `source` is one of: `business-user`, `ai-agent`, `validation-agent`
- [ ] `status` is `unverified`
- [ ] No secrets, credentials, or sensitive data in any field
- [ ] No session-specific or machine-specific paths
- [ ] `source_session` and `source_workspace` are captured
- [ ] Content is fact-based or explicitly framed as `assumption`

## Notes

- **Human review required**: No observation captured through this skill becomes official knowledge automatically
- **v0.1.1 contract**: All type values, field names, and semantics align with the v0.1.1 PRD contract
- **Do not conflate `source`**: It means who originated the claim; the other `source_*` fields are provenance detail
- **Never capture personal operational data**: User-specific paths, local configs, session state
- **Confidence defaults**: 0.7 for normal observations, higher only with strong evidence
