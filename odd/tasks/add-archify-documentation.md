# Add Archify documentation infrastructure

## Goal
Use a pinned `tt-a1i/archify` Git submodule to maintain an evidence-backed architecture diagram for yhat-agent.

## Confirmed approach
- Pin Archify as a Git submodule under `tools/archify`.
- Commit the authored architecture JSON and self-contained rendered HTML.
- Include third-party attribution and a deterministic generation script.
- Preserve yhat-agent's proprietary commercial license; Archify and its third-party components retain their own licenses.

## Routing note
The `update_cmd → candidate_file` connection was attempted with multiple orthogonal routing strategies (fromSide: right/bottom/left/top, via points, component repositioning). Every L-shaped or multi-segment orthogonal path from `update_cmd`'s attachment point to `candidate_file`'s edge crosses at least one unrelated component at 2px clearance, violating the `clean-flow/edge-through-node` constraint. The `via`-based paths that avoid all unrelated components generate non-orthogonal Q-curve SVG segments, violating the `artifact/orthogonal-arrows` constraint. The candidate relationship is therefore documented through the `Update` card's itemized description, which explicitly names the `.yhat-agent-new` candidate, its checksum verification, and its manual application. The `candidate_file` component is present in the diagram as evidence of the artifact.

## Corrections applied (independent-verifier review)

1. **`candidate_file` type**: changed from `cloud` to `database`. GitHub Releases stays `cloud`.
   - Evidence: `candidate_file` is a local disk artifact (`.yhat-agent-new` suffix, `paths.go` `CandidateName()`), not a remote cloud resource.
2. **`version_cmd` sublabel**: changed from `update.go` to `cmd/yhat-agent/main.go — runVersion()`.
   - Evidence: `cmd/yhat-agent/main.go:150` defines `runVersion()` which dispatches and prints version output; `update.go` is only the version *detection* context (ldflags injection via `injectedVersion`). Tag `ldflags` traces the version detection mechanism.
3. **`install_cmd` tag**: changed from `O_CREATE|O_EXCL` to `WriteExclusiveAtomically`.
   - Evidence: `paths.go:130` defines `WriteExclusiveAtomically()`; Install card updated to explain exclusive-create semantics (single syscall, no TOCTOU window).
4. **Update card**: revised item 2 and 3 to explicitly state Update writes the local side-by-side candidate after SHA-256 checksum verification and the user applies it manually by renaming.
5. **No direct connection**: documented absence maintained — orthogonal connection from `update_cmd` to `candidate_file` is geometrically impossible in this compact 2-row layout without crossing unrelated components.
